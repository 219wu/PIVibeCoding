# ADR-0001: P0 工程化：检查点工具化/独立审查/ADR 落盘

- 状态: Accepted
- 日期: 2026-08-11
- 相关任务: P0: 检查点工具化+审查角色独立+ADR决策记录

## 背景（Context）

vibekit 七阶段流水线最初是"提示词协议"：检查点 A/B/C 靠模型自觉跑 git 命令，
审查阶段是同一模型自写自审（同源幻觉/确认偏误），决策理由只在对话里口头说过、
不落盘。对比成熟方案（Claude Code hooks、MetaGPT 角色分离、ADR 实践），
缺工程强制力、缺角色/模型独立性、缺决策可回溯性。

## 决策（Decision）

P0 三项工程化：
1. **检查点工具化**：checkpoint.py 强制 A/B/C，退出码非 0 即阻断（不做就过不去）
2. **独立审查**：prepare_review.py 生成信息隔离的审查输入包（diff+验收标准+指令，
   排除编写者解释），审查切换 deepseek-v4-pro（模型分离）
3. **ADR 落盘**：adr.py 生成 docs/decisions/ADR-NNNN-*.md，⑦集成强制记录

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 |
|------|------|------|
| A: 纯提示词加强（在 SKILL.md 里写更多规则） | 零工作量 | 模型会跳步/忘记，无强制力 |
| B: 工具强制（checkpoint.py 等） | 不做就过不去，对抗"两步退回" | 需开发脚本 |
| C: 跨厂商模型审查（引入 GLM/Qwen） | 错误模式不相关，规避同源幻觉最彻底 | 违反"只使用 DeepSeek"的项目约束 |

## 决策理由（Rationale）

- 选 B 不选 A：项目教训（LangChain 参数丢失）证明"看起来对"不可靠，强制力优先
- 模型分离选"同厂分档"（flash 写 / pro 审）而非跨厂商（方案 C）：
  保住"只用 DeepSeek"底线的同时获得不同档位错误模式；跨厂商留作进阶选项
- 审查信息隔离是核心：光换模型不够，还要让审查者只看到 diff + 验收标准

## 影响（Consequences）

- 正面：检查点无法被跳过；审查脱离同源幻觉；决策可回溯，后续任务可读历史
- 负面 / 代价：每任务多一次工具调用与一次模型切换；新成员需学习工具用法
- 未来可能需要重新审视的触发点：SKILL.md 膨胀后做渐进式披露（P2）；
  若单厂商模型幻觉问题仍频发，引入跨厂商审查（方案 C）
